# Model notes

## Runtime

- Plans are generated by [Hugging Face Inference Providers](https://huggingface.co/docs/inference-providers)
  through the OpenAI-compatible router at `https://router.huggingface.co/v1/chat/completions`. The router
  picks an available provider (Groq, Together, Fireworks, DeepInfra, …) and runs the model on that
  provider's GPUs.
- The **browser** calls the router directly, with the visitor's own token
  (`Authorization: Bearer hf_…`). The router allows cross-origin requests from browsers. The 3DTool
  server never receives the token or the prompts.
- Requests use `temperature: 0`, `max_tokens: 2048` (reasoning models spend tokens before answering)
  and `stream: true`. The app shows reasoning and answer token counts, and stops reading the stream as
  soon as the first JSON object is complete.
- Each attempt times out after 90 s. Invalid output gets one correction retry, as before.
- In-browser CPU models (Transformers.js) were removed at the owner's request.

## Presets

| Preset | Model | Notes |
|---|---|---|
| Fast | `openai/gpt-oss-20b` | Apache-2.0. Reasoning model, served by Groq among others. |
| Balanced (default) | `openai/gpt-oss-120b` | Apache-2.0. Served by many providers. |
| Strong | `Qwen/Qwen2.5-72B-Instruct` | Qwen license. A non-reasoning instruction model. |
| Custom | any router model id | `owner/model`, optionally `:provider`, `:fastest` or `:cheapest`. |

Availability was checked against `https://router.huggingface.co/v1/models` on 2026-10-17. Providers
change their catalogues, so a preset can return 404 later; Custom lets users switch without a code
change.

## Tokens and billing

- Visitors create a fine-grained token with the **"Make calls to Inference Providers"** permission.
- Usage is billed to the visitor's Hugging Face account. PRO accounts include monthly inference
  credits.
- The UI translates HTTP errors into plain messages: 401 (bad token), 402 (credits used up), 403 (no
  access to the model), 404 (model not served) and 429 (rate limited).

## What has been verified

- Unit tests with a mocked `fetch` cover:
  - the request shape, and that the token goes only to the router;
  - SSE parsing of reasoning and content deltas;
  - the early stop once the JSON is complete;
  - the HTTP error messages;
  - errors reported inside the stream;
  - cancellation;
  - no network call at all without a token.
- The router's CORS preflight returns `Access-Control-Allow-Origin: *` and allows the
  `authorization` and `content-type` headers.
- **Not yet verified:** a live generation with a real token, and plan quality for each preset. These
  need the owner's token and have not been run.

## Known limitations

- The app needs an internet connection and a Hugging Face token. Manual editing works without either.
- Prompts and a compact scene summary (object names, kinds, sizes, positions) are sent to Hugging Face
  and the selected provider.
- Model quality and latency vary by provider. A provider may also stop serving a model.
